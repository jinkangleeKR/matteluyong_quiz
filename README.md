# 현장 퀴즈

QR 코드로 참가자를 초대하고, 각 관리자가 자신만의 문제와 게임방을 운영하는 실시간 현장 퀴즈입니다.

## 관리자 사용 순서

1. `/admin.html`에서 이메일과 비밀번호로 관리자 계정을 만들거나 로그인합니다.
2. **퀴즈 만들기**에서 퀴즈 이름과 4개 문항·보기·정답을 작성해 저장합니다. 저장한 문제는 해당 관리자 계정에만 계속 보관됩니다.
3. **게임 진행**에서 저장한 퀴즈를 고르고 시간·점수를 설정해 게임방을 만듭니다.
4. 생성된 QR 코드 또는 링크를 참가자에게 공유합니다. 게임방마다 고유한 초대 링크가 만들어집니다.
5. 대기실 참가자와 채팅을 확인하고 필요하면 내보낸 뒤, `5초 뒤 퀴즈 시작`을 누릅니다.
6. 종료 후 원하는 순간에 `결과 공개`를 누르면 참가자 화면에서 3·2·1 카운트 뒤 점수와 전체 순위가 공개됩니다.

`새 대기실 열기`는 같은 QR 링크를 유지하면서 참가자·답안·채팅 기록을 비웁니다. 게임방이나 저장한 퀴즈는 삭제 버튼을 누르기 전까지 Firebase에 남아 있습니다.

## 참가자 동작

- 공유받은 QR 코드/링크로 들어와 닉네임을 적고 대기실에 입장합니다.
- 시작 전에는 실시간 채팅을 사용할 수 있고, 게임 중에는 채팅이 자동으로 닫힙니다.
- 문항은 모든 참가자에게 같은 시각에 열리고 시간이 끝나면 자동으로 다음 문항으로 이동합니다.
- 답을 고른 뒤 제출해 확정하며, 시간이 남아 있으면 다른 답으로 다시 제출할 수 있습니다.
- 정답 점수는 `정답 점수 + ceil(최대 시간 점수 × 남은 시간 비율)`이고 오답·미응답은 0점입니다.

## Firebase 최초 설정

이 브랜치는 한 Firebase 프로젝트에서 여러 관리자의 데이터를 분리해 보관합니다. 이메일만으로 관리자 권한을 주면 다른 사람이 같은 이메일을 입력해도 접근할 수 있으므로, **이메일/비밀번호 로그인**을 사용합니다.

1. Firebase Authentication에서 **익명 로그인**과 **이메일/비밀번호 로그인**을 켭니다.
2. Firebase Console → Realtime Database → **Rules**에서 [database.rules.json](database.rules.json)의 내용을 전부 붙여 넣고 **Publish**합니다.
3. GitHub Pages 주소인 `jinkangleekr.github.io`가 Authentication → Settings → Authorized domains에 있는지 확인합니다.

`firebase-config.js`에 있는 웹 앱 설정은 이미 이 프로젝트에 연결되어 있습니다. API 키는 브라우저 식별값이며, 실제 데이터 접근은 Realtime Database Rules와 각 로그인한 관리자의 UID로 보호됩니다.

## 데이터 구조

- `quizCatalog/{관리자 UID}`: 관리자가 저장한 문제 세트
- `ownerRooms/{관리자 UID}`: 해당 관리자의 게임방 목록
- `rooms/{게임방 ID}`: 참가자가 읽는 문제·진행 상태·대기실·답안
- `roomSecrets/{게임방 ID}`: 관리자만 읽을 수 있는 정답 키

참가자에게는 진행 중 정답 키가 전송되지 않으며, 결과 공개 시에만 점수 계산에 필요한 정답 정보가 공개됩니다.

## 파일 구성

- `admin.html`, `admin.js`: 로그인, 퀴즈 제작, 게임방 생성·공유·진행
- `index.html`, `app.js`: 참가자 입장, 대기실 채팅, 답안 제출, 결과·순위
- `realtime-store.js`: Firebase 저장소와 로컬 데모 모드
- `database.rules.json`: 다중 관리자용 Realtime Database 보안 규칙
